# Project notes

- Next.js 16 with App Router, TypeScript, React Compiler, typed routes, Sass and Prettier. Import alias is `@/*` (maps to `src`); Sass uses `src` as a load path instead (`@use '_core/styles/_theme'`).
- Part of the shared npm workspace in `C:\Users\adria\projects` (listed in its `package.json` `workspaces`). Packages install to `projects/node_modules`, and there is no lockfile in this repo.
- `next.config.ts` uses `createNextConfig(__dirname)` from `@displaycoffee/alexandria` (in `project-kit/alexandria`). It sets `turbopack.root` and `outputFileTracingRoot` to the parent folder (Next.js only looks for a lockfile inside this Git repo, so without them the dev server can't find `next`), turns on the React Compiler and `typedRoutes`, adds the Sass load path, and lists `@displaycoffee/alexandria` and `@displaycoffee/scripts` in `transpilePackages`. Both ship TypeScript source: local builds pass without it, but Vercel installs them from npm into `node_modules` and the build would fail.
- Every package used here must be listed in this project's own `package.json`. Locally anything in the shared `node_modules` resolves, but Vercel only installs what's listed.
- Deployed on Vercel from the `production` branch: https://alexandria-three.vercel.app. Work happens on `next-template` and is merged into `production` with a pull request. Vercel auto-detects Next.js, so don't add the SPA `vercel.json` rewrite used in the Vite projects.
- Sibling projects (portfolio, burmecia, etc.) are Vite + TanStack Router and share `@displaycoffee/*` packages (tokens, styles, scripts) from `project-kit`. Tokens live in `src/_core/tokens/*.json` and are built with `tokens-generate`, which `build` runs first.
- `npm run dev` runs `alexandria dev`, not `next dev` directly: it runs the token and icon generators, starts `next dev --experimental-https` (extra args pass through, e.g. `npm run dev -- --port 3001`), and re-runs a generator when its sources change (`src/_core/tokens/*.json` except `theme.json`, and `src/_core/data/icons.json`). Turbopack has no plugin API for this, so it can't live in `next.config.ts` like Burmecia's `tokensWatch()` Vite plugin.
- Tokens drive the `<head>` the same way Burmecia's `src-generate.js` does: `src/layout/head/scripts/head.ts` calls `createHead()` from `@displaycoffee/alexandria`, and `app/layout.tsx` uses it for metadata, viewport theme colors, font preloads and `@font-face` styles. `app/manifest.ts` builds the manifest. Fonts stay in `public/assets/fonts` (not `next/font`, which can't read token data) so the token paths keep working.
- Icons use `@iconify/react` (Turbopack can't run `unplugin-icons`, which the Vite projects use). List icon names in `src/_core/data/icons.json`, grouped by Iconify set prefix (each set needs `@iconify-json/<prefix>` as a devDependency). Lucide names stay plain (`'x'`), other sets are keyed `'prefix:name'` (`'mdi:home'`). `alexandria icons` (run by `dev` and `build`, and re-run by `dev` when `icons.json` changes) writes only those icons' SVG data into `src/_core/data/icons.ts`. Don't edit `icons.ts` by hand.
- Next 16 error boundaries (`error.tsx`, `global-error.tsx`) receive `retry`, not `reset`.

# Conventions

- **Server components by default.** Only the pieces that need hooks, event handlers or browser APIs get `'use client'`, in a `*Client.tsx` file next to the component (`ContainerClient`, `BlocksClient`, `FormsClient`, `NavigationClient`). Import client pieces from the `*Client` file directly; don't re-export them (that causes circular imports). Server content passed to a client component as `children` stays on the server.
- Client components still render on the server once, so `window`, `document` and `localStorage` may only be used in effects, event handlers or `useSyncExternalStore` (`useRespond` and `ThemeToggle` show the pattern). Never at the top level of a module or during render.
- **Route groups** set the layout: pages in `app/(sidebar)` get `ContainerSidebar`, pages in `app/(full)` get `ContainerFull`. A folder can exist in both groups as long as each URL has one `page.tsx` (Page Two is in `(full)`, its children in `(sidebar)`). `not-found.tsx` and `error.tsx` render in the root layout, so they wrap themselves in `ContainerFull`.
- Page titles: keep the title in its own `const title` and use it in both `metadata` and the page, rather than reading `metadata.title` (typed `string | TemplateString`).
- **Navigation** data (`components/navigation/scripts/navigation.ts`) is the source of truth for URLs: the nav, the sitemap (`app/sitemap.ts`, items with `includeInSitemap`), and parent links on child pages (`navigationUtils.get.listItem`) all read it. Its urls are typed as `Route` with one cast in `navigationUtils.create`, since they're built from keys at runtime; keep keys in sync with `app/` folders.
- **Desktop / mobile navigation** both render; `hideMobile` / `hideDesktop` classes switch them with CSS so the server HTML is right on first paint. `useRespond` is only for behavior after load (e.g. `Slideout` treats itself as closed on desktop when `hideDesktop` is set). Don't use it to choose what renders.
- **Page view transitions** are started by `NavigationLink` with `useViewTransition` (`layout/container/scripts/container-hooks.ts`), which names `.content` `page-content` for `content.scss`. Don't use React's `<ViewTransition>`: it starts a document view transition on page load, which shifts the content in Firefox. Cross-group navigations create a new `.content`, so the hook names that one too.
- **Images**: `components/image/Image.tsx` wraps `next/image` with a state-based error fallback. Only images with `width` and `height` get an optimized 1x / 2x `srcset`; fluid, bg and dimensionless images are `unoptimized` (a `sizes`-based srcset locked the natural width at load, and `fill` overrode `image.scss`).
- **Theme**: `ThemeToggleScript` (in `<head>`) applies a saved theme before first paint, and `<html>` has `suppressHydrationWarning` for that. `ThemeToggle` renders the default theme on the server and reads the real one after hydration.
- ESLint uses Next's presets plus the full `jsx-a11y` recommended rules (matching the Vite projects).
