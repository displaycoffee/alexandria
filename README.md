# Alexandria - version 0.1.0

Next.js-based framework to create projects. Like [Burmecia](https://github.com/displaycoffee/burmecia), its React / Vite sibling, it contains very basic styles so that the template may be used as a boilerplate to create something better. [Preview here.](https://alexandria.display.coffee)

This is named after the kingdom in the game Final Fantasy IX -- home to Princess Garnet and the castle at the center of the story.

### public

- Static assets are stored here and served from the site root.
- Favicons are loaded into the root of this directory, mostly so `favicon.ico` displays in the browser.
- Fonts stay in `public/assets/fonts` (not `next/font`), so the paths in the font tokens keep working.

### Build scripts

The build scripts come from [`@displaycoffee/alexandria`](https://www.npmjs.com/package/@displaycoffee/alexandria) and [`@displaycoffee/tokens`](https://www.npmjs.com/package/@displaycoffee/tokens), and are run through the commands in `package.json`.

- **alexandria dev** - Runs `npm run dev`: builds tokens and icons, starts `next dev --experimental-https`, and rebuilds them when their source files change. Extra arguments are passed to Next, e.g. `npm run dev -- --port 3001`.
- **alexandria icons** - Builds `src/_core/data/icons.ts` from the icon names in `src/_core/data/icons.json`, so only those icons are bundled.
- **tokens-generate** - Compiles all tokens from `src/_core/tokens` into `src/_core/styles/_root.scss` (CSS custom properties, including dark mode), `src/_core/styles/_theme.scss` (Sass variables), and `src/_core/tokens/theme.json` (resolved values for scripts).

### src

- Dev environment is started with `npm run dev`.
- Organized directories into folders as: `app` (routes, layouts, and metadata files), `components` (shared elements), `context` (shared values like `theme`, `utils`, and `variables`), and `layout` (layout elements).
- **app** - Pages live in route groups, which don't change the URL:
    - `(sidebar)` pages show the sidebar next to their content, and `(full)` pages use the full width. Move a page folder between them to change its layout.
    - A folder can exist in both groups as long as each URL has only one `page.tsx` (e.g. `(full)/page-two` with its children in `(sidebar)/page-two`).
    - `manifest.ts`, `robots.ts`, and `sitemap.ts` are generated by Next. The sitemap is built from the navigation data, so new pages need a navigation item (it can be hidden with `showInNav: false`) or an entry in `sitemap.ts`.
- **Server and client components** - Components are server components by default. Pieces that need hooks, event handlers, or the browser are split into `*Client.tsx` files next to them (e.g. `FormsClient.tsx`, `NavigationClient.tsx`) and imported from there directly.
- `_core` directory holds functions, data, tokens, and styles used throughout the app.
    - **data** - These scripts read `src/_core/tokens/theme.json` (and `package.json` for `site.ts`) and shape it for the app. `icons.json` lists the icons to bundle; don't edit `icons.ts` by hand.
    - **scripts** - Helper functions, variables, and global TypeScript definitions are here. Shared utils and hooks come from [`@displaycoffee/scripts`](https://www.npmjs.com/package/@displaycoffee/scripts).
    - **styles** - `_root.scss` and `_theme.scss` are generated from tokens. If you edit these, the changes will be removed later when generation happens again. Sass helper mixins and functions come from [`@displaycoffee/styles`](https://www.npmjs.com/package/@displaycoffee/styles), e.g. `@use '@displaycoffee/styles/mixins';`. `src` is a Sass load path, so project styles are imported without relative paths, e.g. `@use '_core/styles/_theme';`.
    - **tokens** - The place to customize design tokens. They work the same as in Burmecia (see its README for the `$extensions` options and theme settings).

### other

- **package.json** - Check out the `scripts` section for all the commands. `npm run dev` and `npm run build` are going to be the main scripts, along with `npm run lint` and `npm run format`. The `displayName` prop sets the title, Open Graph title and site name, and the manifest `short_name`. The `description` and `homepage` props set the meta description and site URL.
- **next.config.ts** - Uses `createNextConfig()` from `@displaycoffee/alexandria`, which turns on the React Compiler and typed routes, sets up the shared workspace, and adds the Sass load path. Project-specific options go in its second argument.
